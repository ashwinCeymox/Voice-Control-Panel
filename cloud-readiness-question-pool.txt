================================================================================
 CLOUD READINESS QUESTION POOL
 Voice AI platform: FastAPI gateway + LocalAI + local-tts + browser Silero VAD
================================================================================

PURPOSE
-------
We plan to move this platform to a cloud (Linux) server and offer its models to
other projects through API keys. Before a design is chosen, the facts below must
be collected. Answer every question you can from the code, configuration and
tests. Do not guess.

HOW TO ANSWER
-------------
1. Do NOT change any source code. Read, run commands and run tests only.
2. Write answers to: docs/cloud-readiness-answers.md
3. Use exactly this format for every question:

     ID:          (for example C-04)
     Status:      ANSWERED | PARTIAL | UNKNOWN | NEEDS OWNER
     Answer:      (short and specific)
     Evidence:    (file path and line numbers, command and its output, or test result)
     Confidence:  high | medium | low

4. If a fact cannot be found in code or by testing, set Status to UNKNOWN and
   say what would be needed. If the question needs a business decision, set
   Status to NEEDS OWNER and do not invent an answer.
5. Measure, do not estimate. For every timing test, run at least 5 times and
   report the median and the slowest result (p95 or max).
6. Record the machine used for each measurement: chip or CPU, RAM, OS, and
   whether LocalAI and local-tts were already warm.
7. Never print secrets, tokens or full API keys in the answers.
8. Finish with a short list titled "Top 10 risks for cloud deployment", ordered
   by how likely they are to break the service.

 SECTION C - MEASUREMENTS AND TESTS (run, record, report)
================================================================================

C-01  STT speed by model. For each installed STT model, transcribe the same set
      of test clips (short 2 s, medium 5 s, long 15 s). Report time per clip and
      real-time factor. Also record memory used by LocalAI after loading it.
C-02  LLM speed by model. For each installed LLM, record time to first token and
      tokens per second for a 20-token and a 200-token reply. Record memory.
C-03  TTS speed. Record time to first audio chunk and real-time factor for a
      short and a long sentence. Record memory.
C-04  End-to-end latency. Record for 20 voice turns: silence wait, STT time, LLM
      first token, time to first clause, TTS first audio, total from speech end
      to first audio. Report median and slowest.
C-05  Cold start. Time from process start to ready for LocalAI, local-tts and the
      gateway. Time for the first request after a model switch.
C-06  Concurrency test on STT. Send 1, 2, 5 and 10 simultaneous transcription
      requests. Report total time, per-request time, errors and timeouts.
C-07  Concurrency test on the LLM. Same pattern with chat completions. Record
      whether LocalAI queues or runs requests in parallel.
C-08  Concurrency test on TTS. Same pattern.
C-09  Concurrency test on the voice pipeline. Run 1, 2, 3 and 5 simultaneous
      voice sessions (scripted audio). Report latency per session, memory peak
      and any failure.
C-10  Memory peak with all services loaded and one active voice session, and
      again with 3 sessions.
C-11  Does LocalAI transcription with response_format=verbose_json return segment
      details (start, end, avg_logprob, no_speech_prob, compression_ratio)?
      Include one real response.
C-12  Does LocalAI transcription with stream=true return partial text while
      processing, or only after completion? Include timing evidence.
C-13  Hallucination test. Send 10 clips of silence, fan noise, keyboard noise,
      music, a cough and TV speech. Report which transcripts reach the LLM. List
      any common Whisper silence phrases that pass the current gates (for
      example "Thank you.").
C-14  Barge-in test with laptop speakers and with headphones: number of false
      interruptions in 10 minutes, and delay between user speech start and
      playback stop.
C-15  Failure behavior. Kill LocalAI during a request, kill local-tts during
      synthesis, and disconnect the client during a turn. Report what the
      client receives and whether the gateway recovers without a restart.
C-16  Model install and delete test. Install and delete one small STT model and
      one small LLM through the gallery API. Report whether it appears in
      installed models, how long it takes, and whether any files remain.
C-17  Long-running test. Run 30 consecutive voice turns. Report memory growth,
      leaked tasks or sockets, and latency drift.
C-18  Request size limits. Send an oversized audio file and a very long TTS text.
      Report the response and whether the server stays healthy.
