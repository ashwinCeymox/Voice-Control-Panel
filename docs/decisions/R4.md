- **Status**: Proposed / Recommended
- **Author**: Researcher R3 & R4

- **Target Hardware**: Apple MacBook Air M2, 8 GB Unified Memory

---

## 1. Question

> **How do LocalAI and local-tts expose gallery, model installation, and progress? What metadata exists (size, backend, license, voice gender), and how should the platform manage downloads and voice categorization?**

Users need to browse an Explore gallery of STT, LLM, and TTS models, inspect disk size, memory fit, backend, and license, trigger installations without hanging the browser, monitor live download progress, and select TTS voices with accurate gender and accent labels (`female` / `male` / `unknown`). Because LocalAI and `local-tts` have different APIs and capabilities (and `local-tts` lacks a dynamic model download API), what unified architecture should the local voice agent gateway implement?

---

## 2. Options Considered

| Option | Architecture & Transport | Progress Tracking | Voice Gender & Metadata | Overhead on 8 GB | Feasibility & Stability |
|---|---|---|---|---|---|
| **Option 1: Direct Synchronous Passthrough (Simplest / Naive)** | Synchronous HTTP calls directly to LocalAI `/models/apply`; synchronous disk writes for TTS. | No progress feedback; requests block for 1–5 minutes or time out; tab refresh loses context. | Hardcoded fallback (`gender: "unknown"` for all voices). | Low memory, but broken UX. | **Unacceptable**: Browser timeouts, frozen UI, zero download visibility. |
| **Option 2: Unified Asynchronous Job Manager with Polling** ⭐ *(Recommended)* | Gateway-managed background tasks (`asyncio` / FastAPI) with thread-safe job store. Unified endpoints `POST /v1/models/install` and `GET /v1/models/install/{job_id}`. | Resilient client polling (750ms–1000ms) returning bytes downloaded, total bytes, speed (MB/s), ETA, and status. | Automated Kokoro prefix parser (`af_`, `am_`, `bf_`, `bm_`), inferred language/gender, SQLite user override store (`PUT /v1/voices/{id}/meta`). | **Zero external dependencies**, $<15\text{ MB}$ RAM overhead. | **Optimal**: Highly reliable across browser reloads, clean error handling, atomic disk writes. |
| **Option 3: Distributed Task Queue + SSE / WebSocket Streaming** | Celery / RQ worker with Redis broker; Server-Sent Events (SSE) or WebSocket push for progress. | Real-time push updates. | Complex distributed metadata sync. | High: Redis daemon + Celery workers consume ~150–250 MB RAM and add substantial process management complexity. | **Overkill**: Unnecessary overhead and maintenance burden for a single-machine local voice agent. |

---

## 3. Evaluation Criteria (Weighted)

1. **Reliability & Progress Visibility (Weight: 30%)**: Downloads of 1–2 GB LLM weights or 150 MB Whisper models over variable internet connections must show real-time percentage and byte counts, survive browser refreshes, and gracefully recover or report actionable errors.
2. **Minimal Memory & Process Footprint on 8 GB (Weight: 25%)**: Must run in-process within the FastAPI gateway without requiring external brokers (Redis/RabbitMQ) that steal RAM from the AI models.
3. **Simplicity & Maintainability (Weight: 20%)**: Clear separation of concerns, clean REST contract, and easy-to-mock interfaces for contract and UI testing.
4. **Safety & Disk Sandboxing (Weight: 15%)**: Strict path traversal validation (`S-REVIEW` gate), atomic file renaming (`.part` $\to$ final), and validation of download sources.
5. **Metadata Fidelity (Weight: 10%)**: Accurate extraction of size, license, backend, parameter counts, and voice attributes (gender, language, accent).

## 4. Deep Analysis of Provider Capabilities

### 4.1 LocalAI Gallery Architecture & Endpoints

LocalAI provides an integrated model gallery subsystem configured via model repositories:

- **`GET /models/available`**:
  Returns a curated list of models from configured galleries (e.g. LocalAI standard gallery). Each item provides:
  - `name`: Model identifier (e.g. `whisper-base`, `llama-3.2-1b-instruct`, `qwen2.5-1.5b-instruct`).
  - `description`: Text and markdown explanation of model capabilities.
  - `license`: Open-source license identifier (`Apache-2.0`, `MIT`, `Llama-3.2-Community`).
  - `urls`: Model card, repository, or paper URLs.
  - `icon`: Avatar / icon URL.
  - `tags`: Filter tags (`stt`, `llm`, `tts`, `whisper`, `llama-cpp`).
  - `files`: Array of file objects specifying `filename`, `sha256`, and download `uri`.
  - `config_file`: YAML configuration template defining the model runtime backend (e.g. `backend: llama-cpp` or `backend: whisper`).
  - `size`: Uncompressed / download size in bytes.
- **`POST /models/apply`**:
  Installs a model from the gallery or from an external YAML URL:
  ```json
  {
    "id": "qwen2.5-1.5b-instruct",
    "name": "qwen2.5-1.5b"
  }
  ```
  LocalAI downloads the model files and registers the configuration in its `$MODELS_PATH`. In LocalAI 2.10+, this can run asynchronously and returns a job tracking identifier.
- **`GET /models/jobs` and `GET /models/jobs/{job_id}`**:
  Tracks ongoing LocalAI background download jobs, reporting `in_progress`, `completed`, `failed`, and progress percentage.
- **`GET /v1/models`**:
  OpenAI-compatible listing of currently installed and loaded models.
- **`/api/models/estimate/*`**:
  LocalAI estimation endpoints that project VRAM and context RAM for a given quantization and parameter size.

### 4.2 local-tts Architecture & HuggingFace Hub Cache

[`saghul/local-tts`](https://github.com/saghul/local-tts) is a lightweight Python service serving Kokoro (and optionally Pocket/Kitten/Qwen engines):

- **Model Weights & Cache**:
  - Kokoro-82M weights (`kokoro-v0_19.pth` or `.onnx`, ~320 MB) and voice style tensors (`voices/`, ~1.2 MB per voice) are fetched from Hugging Face Hub (`hexgrad/Kokoro-82M`).
  - Cached in the standard Hugging Face directory: `~/.cache/huggingface/hub/models--hexgrad--Kokoro-82M/snapshots/<revision>/`.
- **Existing Endpoints in local-tts**:
  - `GET /v1/models`: Returns supported engine identifiers (`[{"id": "kokoro", "name": "Kokoro (Default)"}, ...]`).
  - `GET /v1/voices?model_id=kokoro`: Lists available voice IDs (`af_heart`, `am_adam`, `bf_emma`, etc.).
  - `POST /v1/audio/speech`: OpenAI-compatible speech synthesis.
  - `POST /v1/text-to-speech/{voice_id}/stream`: ElevenLabs-compatible streaming speech synthesis.
- **Key Architectural Limitation**:
  - `local-tts` does **not** provide a dynamic gallery browsing or installation REST API. It expects weights to be pre-downloaded or pulled on cold start via `huggingface_hub`.
- **Gateway Abstraction Solution**:
  - The local voice agent gateway (`app/api/gallery.py` / `S-MODELS`) bridges this gap:
    1. It hosts a curated registry of supported TTS models (Kokoro-82M, Pocket-TTS, KittenTTS).
    2. When a user installs a TTS model via `POST /v1/models/install`, the gateway download worker streams the HuggingFace weights or executes `hf_hub_download` into the shared local cache.
    3. It registers the new engine/voice with `local-tts` and refreshes the local voice catalogue.

## 5. Voice Gender & Metadata Taxonomy

### 5.1 Kokoro Voice Naming Convention

Kokoro voice files follow a strict structural naming convention:
```
<accent_code><gender_code>_<voice_name>
```

| Prefix | Accent / Language | Gender | Examples |
|---|---|---|---|
| **`af_`** | American English (`en-US`) | **Female** | `af_heart` (Default), `af_bella`, `af_nicole`, `af_sarah`, `af_sky`, `af_aoede` |
| **`am_`** | American English (`en-US`) | **Male** | `am_adam`, `am_michael`, `am_eric`, `am_fenrir`, `am_puck` |
| **`bf_`** | British English (`en-GB`) | **Female** | `bf_emma`, `bf_isabella`, `bf_alice`, `bf_lily` |
| **`bm_`** | British English (`en-GB`) | **Male** | `bm_george`, `bm_lewis`, `bm_daniel`, `bm_fable` |
| **`jf_` / `jm_`** | Japanese (`ja-JP`) | Female / Male | `jf_alpha`, `jm_kento` |
| **`zf_` / `zm_`** | Mandarin Chinese (`zh-CN`) | Female / Male | `zf_xiaoyan`, `zm_yunjian` |
| **`ef_` / `em_`** | Spanish (`es-ES`) | Female / Male | `ef_dora`, `em_alex` |
| **`ff_` / `fm_`** | French (`fr-FR`) | Female / Male | `ff_siwis`, `fm_pierre` |

### 5.2 Regular Expression Parser

```python
import re
from typing import Dict, Any

KOKORO_PATTERN = re.compile(r"^([a-z])([fm])_(.+)$")

LANG_MAP = {
    "a": ("en-US", "American English"),
    "b": ("en-GB", "British English"),
    "j": ("ja-JP", "Japanese"),
    "z": ("zh-CN", "Mandarin"),
    "e": ("es-ES", "Spanish"),
    "f": ("fr-FR", "French"),
    "i": ("it-IT", "Italian"),
    "p": ("pt-BR", "Portuguese"),
}

def parse_voice_metadata(voice_id: str) -> Dict[str, Any]:
    """Extracts gender, accent, language, and display name from voice_id."""
    match = KOKORO_PATTERN.match(voice_id.strip().lower())
    if match:
        lang_code, gender_code, raw_name = match.groups()
        gender = "female" if gender_code == "f" else "male"
        lang_tag, accent_name = LANG_MAP.get(lang_code, ("unknown", "Unknown"))
        display_name = f"{raw_name.replace('_', ' ').title()} ({accent_name} {gender.title()})"
        return {
            "voice_id": voice_id,
            "name": display_name,
            "gender": gender,
            "language": lang_tag,
            "accent": accent_name,
            "source": "inferred",
        }
    
    # Fallback for non-standard / custom voices
    return {
        "voice_id": voice_id,
        "name": voice_id.replace("_", " ").title(),
        "gender": "unknown",
        "language": "unknown",
        "accent": "unknown",
        "source": "metadata",
    }
```

### 5.3 Manual Override API & SQLite Store

When an engine or custom imported voice cannot be parsed automatically, users can override attributes in the UI (`U5` / `U7`):

- **Database Table**: `voice_metadata`
  ```sql
  CREATE TABLE IF NOT EXISTS voice_metadata (
      voice_id TEXT PRIMARY KEY,
      name TEXT NOT NULL,
      gender TEXT CHECK(gender IN ('male', 'female', 'unknown')) NOT NULL,
      language TEXT NOT NULL,
      accent TEXT,
      source TEXT CHECK(source IN ('metadata', 'inferred', 'manual')) NOT NULL,
      updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
  );
  ```
- **Endpoint**: `PUT /v1/voices/{voice_id}/meta`
  ```json
  {
    "name": "Custom Narrator",
    "gender": "male",
    "language": "en-US",
    "accent": "Mid-Atlantic"
  }
  ```
- **Response**: Updates database and returns the voice object with `source: "manual"`.

## 6. Asynchronous Install Job Manager Specification

### 6.1 Job State Lifecycle

```
       ┌───────────┐
       │  QUEUED   │
       └─────┬─────┘
             │ (Worker thread begins HTTP stream)
             ▼
       ┌───────────┐
       │DOWNLOADING│ ──(Progress: 0% → 99%, bytes, speed, ETA)
       └─────┬─────┘
             │ (Download complete, verifying SHA256 checksum)
             ▼
       ┌───────────┐
       │ VERIFYING │
       └─────┬─────┘
             │ (Atomic rename .part → target file, register model)
             ▼
       ┌───────────┐
       │ COMPLETED │
       └───────────┘
             │ (On error, timeout, or SHA256 mismatch)
             ▼
       ┌───────────┐
       │  FAILED   │ ──(Includes actionable error_message)
       └───────────┘
```

### 6.2 Data Model

```python
from datetime import datetime
from enum import Enum
from typing import Optional
from pydantic import BaseModel, Field

class InstallStatus(str, Enum):
    QUEUED = "queued"
    DOWNLOADING = "downloading"
    VERIFYING = "verifying"
    COMPLETED = "completed"
    FAILED = "failed"
    CANCELLED = "cancelled"

class InstallJob(BaseModel):
    job_id: str
    model_id: str
    category: str  # "stt", "llm", "tts"
    provider: str  # "localai", "localtts"
    status: InstallStatus
    progress: float = Field(0.0, ge=0.0, le=100.0)
    downloaded_bytes: int = 0
    total_bytes: int = 0
    speed_mbps: float = 0.0
    eta_seconds: Optional[int] = None
    error_message: Optional[str] = None
    created_at: datetime
    updated_at: datetime
```

### 6.3 REST Endpoints Contract (`app/api/gallery.py`)

#### 1. Start Installation: `POST /v1/models/install`
- **Request Body**:
  ```json
  {
    "model_id": "qwen2.5-1.5b-instruct",
    "provider": "localai",
    "category": "llm"
  }
  ```
- **Response `202 Accepted`**:
  ```json
  {
    "job_id": "job_inst_e4a8b79c",
    "model_id": "qwen2.5-1.5b-instruct",
    "status": "queued",
    "progress": 0.0,
    "message": "Model installation queued"
  }
  ```

#### 2. Poll Installation Progress: `GET /v1/models/install/{job_id}`
- **Response `200 OK`**:
  ```json
  {
    "job_id": "job_inst_e4a8b79c",
    "model_id": "qwen2.5-1.5b-instruct",
    "status": "downloading",
    "progress": 42.6,
    "downloaded_bytes": 418290124,
    "total_bytes": 982000000,
    "speed_mbps": 18.4,
    "eta_seconds": 31,
    "error_message": null
  }
  ```

#### 3. Polling Protocol for Frontend (`U2` Models Page)
1. Frontend calls `POST /v1/models/install` upon user clicking **Download** / **Install**.
2. Frontend immediately displays an active progress bar with percentage, speed, and ETA badge.
3. Frontend polls `GET /v1/models/install/{job_id}` every **800ms**.
4. When `status === "completed"`, polling stops, a success toast appears, and the model moves from "Explore" to "Installed".
5. When `status === "failed"`, polling stops and an error banner displays `error_message` with a retry button.

### 6.4 Security, Sandboxing & Atomic Disk Writes (`S-REVIEW` Gate)

To comply with safety rules reviewed by `S-REVIEW` (`V1`):
1. **Strict Path Sandboxing**:
   - Downloads are restricted exclusively to the resolved models directory:
     ```python
     base_dir = os.path.realpath(settings.MODELS_DIR)
     target_file = os.path.realpath(os.path.join(base_dir, safe_filename))
     if not target_file.startswith(base_dir + os.sep):
         raise SecurityError("Path traversal attempt detected")
     ```
   - Disallow symlinks, relative path traversal (`..`), or shell meta-characters.
2. **Atomic Writes with `.part` Extension**:
   - Files are downloaded to `<filename>.<job_id>.part`.
   - On successful download and SHA256 checksum verification, `os.replace` atomically renames `.part` to final filename.
   - If download fails or is cancelled, `.part` files are deleted immediately to avoid orphaned disk bloat.
3. **Pre-flight Disk Check**:
   - Verify host free disk space $\ge \text{Total File Size} + 5,000\text{ MB}$ before allowing download to begin. If space is insufficient, reject with `400 Bad Request` and explain required free space.

## 8. Recommendation & Confidence

- **Recommendation**:
  1. **Adopt Option 2 (Unified Asynchronous Job Manager with Polling)**:
     - Implement in `app/api/gallery.py` and `app/services/install_manager.py` (`B2`).
     - Standardize install tracking on `POST /v1/models/install` and `GET /v1/models/install/{job_id}`.
     - Use 800ms client polling in frontend (`U2`).
  2. **Implement Kokoro Prefix Gender Detection with SQLite Fallback**:
     - Parse `af_`, `am_`, `bf_`, `bm_` prefix automatically in `app/api/tts.py` (`B3`).
     - Support `PUT /v1/voices/{id}/meta` for user overrides stored in `voice_metadata` SQLite table.
     - Extended voice schema returns `gender` (`male` / `female` / `unknown`), `language`, `accent`, and `source` (`metadata` / `inferred` / `manual`).
  3. **Enforce Atomic Downloads & S-REVIEW Path Sandboxing**:
     - Require atomic `.part` download semantics and pre-flight disk check ($>5\text{ GB}$ free) before initiating downloads.
- **Confidence**: **High**. Tested against `saghul/local-tts` voice catalogue and LocalAI OpenAPI specifications.

### 8.1 Riskiest Assumption
The riskiest assumption is that a remote model download repository or HuggingFace endpoint suffers network throttling, packet loss, or changes its download URL format, causing the download worker to stall indefinitely if timeouts are not strictly enforced.
