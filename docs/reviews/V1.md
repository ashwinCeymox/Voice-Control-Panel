## 2. Vector-by-Vector Audit Findings & Mitigations

### 2.1 Path Traversal & Parameter Validation (`app/api/gallery.py`)
- **Vulnerability Identified:**
  - `model_id` input in `POST /v1/models/install` and `DELETE /v1/models/{id}` previously permitted non-string types (causing unhandled `TypeError` 500 server crashes) and had no upper bound on string length.
  - Previous regex allowed leading periods/dots (e.g. `.hidden_file`), which could reference hidden dotfiles, or leading hyphens (e.g. `-flag`), which poses argument injection risks.
- **Remediation Implemented:**
  - Implemented centralized `validate_model_id()` in `app/api/gallery.py`.
  - Enforced:
    1. Strict type checking (`isinstance(model_id, str)`).
    2. Length bounding (`1 <= len(model_id) <= 128`).
    3. Strict character pattern: must start with an alphanumeric character (`^[a-zA-Z0-9]`), followed only by alphanumeric, underscores, hyphens, and periods (`[a-zA-Z0-9_\-\.]*$`).
    4. Explicit rejection of directory traversal sequences (`..`, `/`, `\`).
- **Status:** **PASS**

---

### 2.2 Unsafe File Unlink & Directory Scoping (`app/api/gallery.py`)
- **Vulnerability Identified:**
  - Model deletion endpoint (`DELETE /v1/models/{id}`) is currently a catalog/status stub. However, without strict path sandboxing on `{id}`, any future direct file unlink would have been vulnerable to path escape outside the storage directory.
- **Remediation Implemented:**
  - Unified input validation through `validate_model_id()` ensures no path separators or traversal sequences can enter the uninstallation logic.
  - Slashes (`/` and `\`), directory traversals (`..`), current directory tokens (`.`), and control characters are rejected with HTTP 400.
- **Status:** **PASS**

---

### 2.3 Secrets in Logs & Data Leakage (`app/core/logging.py`)
- **Vulnerability Identified:**
  - `app/core/logging.py` previously only redacted `Bearer` tokens and simple `xi-api-key: ...` or `ticket=...` strings.
  - Sensitive keys represented in JSON payloads (e.g. `{"ticket": "..."}`, `{"api_key": "..."}`, `{"password": "..."}`) or alternate delimiter formats were unredacted.
- **Remediation Implemented:**
  - Enhanced `SENSITIVE_PATTERNS` in `app/core/logging.py` to scrub:
    1. Bearer tokens: `Bearer <token>`
    2. API keys and passwords: `((?:xi-api-key|api[_-]?key|ticket|token|secret|password)\s*[:=]\s*)`
    3. JSON serialized credentials: `("?(?:ticket|api_key|apiKey|token|secret|password)"?\s*:\s*")[^"]+(")`
  - Audited all logger calls across `app/`: user prompt contents and transcripts are stored in SQLite and are not logged to stdout.
- **Status:** **PASS**

---

### 2.4 Memory Safety & Concurrency Integrity (`app/services/agent_manager.py`)
- **Vulnerability Identified:**
  - **Concurrency Race Condition:** `AgentManager.load_agent` updated global state variables (`_ACTIVE_AGENT_ID`, `_ACTIVE_LOAD_STATE`) without synchronization. Concurrent load requests could interleave, leaving inconsistent states.
  - **State Hang on Failure:** If an unexpected hardware or database exception occurred after `_ACTIVE_LOAD_STATE = "loading"`, the state was left permanently stuck in `"loading"`.
- **Remediation Implemented:**
  - Added `_LOAD_LOCK = asyncio.Lock()` in `app/services/agent_manager.py`.
  - Wrapped `load_agent` within `async with _LOAD_LOCK:` to serialize concurrent agent loads.
  - Added robust exception handling: if any failure occurs during the load sequence, `_ACTIVE_LOAD_STATE` is set to `"error"` and previous state is protected from corrupted partial writes.
- **Status:** **PASS**

---

### 2.5 Microphone Error Handling & Resource Leaks (`vad.ts` & `Assistant.tsx`)
- **Vulnerabilities Identified:**
  - **Dangling Stream on Init Error:** When `getUserMedia` threw permission denial or device missing errors, or when subsequent AudioContext/MediaRecorder initialization failed, `audioStreamRef` was not stopped, leaving the browser mic capture icon active.
  - **AudioContext & Interval Leaks:** On turn completion (`stopListening()`), `vadRef.current.stop()` was omitted and `audioCtxRef.current.close()` was not called. Because a new `AudioContext` and `BrowserVAD` instance were created per turn, browser AudioContext limits (~6 contexts) were rapidly exhausted and background 50fps `setInterval` timers accumulated indefinitely.
  - **Unhandled AudioContext Exceptions in VAD:** If an AudioContext was closed while `BrowserVAD._tick()` was in flight, `analyser.getByteTimeDomainData` could throw uncaught DOMExceptions.
- **Remediation Implemented:**
  - **Lifecycle Cleanup:** Updated `cleanupAudio()` and `stopListening()` in `Assistant.tsx` to explicitly stop `mediaRecorderRef`, invoke `vadRef.current.stop()`, stop all `audioStreamRef` tracks, disconnect and close `audioCtxRef`, and reset references.
  - **User-Friendly Error Handling:** Intercepted `NotAllowedError` and `NotFoundError` to display descriptive warnings ("Microphone access denied..." / "No microphone found...") without crashing the UI.
  - **Defensive VAD Tick:** Wrapped `_getRMS()` in `vad.ts` with error handling to silently abort if the context/node is closed, and explicitly disconnected the input source node from the analyser on `stop()`.
- **Status:** **PASS**
