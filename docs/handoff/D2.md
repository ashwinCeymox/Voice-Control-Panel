## 1. Executive Summary

Task D2 delivers the usage telemetry and analytics engine for the Developer Dashboard:
1. `usage_events` database schema and recording pipeline capturing endpoint, latency, TTFB, status codes, and input/output units.
2. Analytics summary API with latency percentiles (p50, p95), success rate, unit totals, and dimension breakdowns.
3. Time-series rollups bucketed by hour or day.
4. Filterable, paginated request event log with CSV export capability.
5. Model status inspection (warm vs. idle states, RAM footprint, system memory).
6. Strict privacy preservation: zero audio recordings, prompt text, transcripts, or model outputs are ever captured or exported.

---

## 2. API Endpoints

| Method | Path | Query Parameters | Description |
|---|---|---|---|
| `GET` | `/v1/admin/usage/summary` | `since` (e.g. 1h, 24h, 7d, 30d), `until`, `group_by` (model/endpoint/key/profile) | Total requests, errors, 429/503 counts, p50/p95 latency, TTFB, units, groups |
| `GET` | `/v1/admin/usage/timeseries` | `interval` (hour/day), `since`, `until`, `key_id`, `profile_id`, `model` | Chronological series of points for time-series charts |
| `GET` | `/v1/admin/usage/requests` | `limit`, `offset`, `key_id`, `profile_id`, `endpoint`, `status`, `since`, `export` (csv) | Paged request log or downloadable CSV file |
| `GET` | `/v1/admin/models/status` | None | Installed model statuses (`warm` vs `idle`), memory, and host system RAM |

---

## 3. Privacy & Compliance Guarantees

- **No Content Logging:** The `usage_events` schema stores solely numerical metrics, model IDs, endpoint paths, HTTP status codes, latency timings, and quota units.
- **Export Anonymity:** CSV exports contain request ID, timestamp ISO, key prefix, profile name, latency, units, and status. Under no circumstance do user prompts or audio bytes enter the export.
- **Role Enforcement:** Non-admin caller keys receive HTTP 403 (`FORBIDDEN`) on all `/v1/admin/usage/*` and `/v1/admin/models/status` endpoints.
