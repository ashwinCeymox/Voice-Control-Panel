## 1. Network Topology & Security Perimeter

In accordance with Phase 1 and Phase 2 architecture principles, internal backends are completely isolated from external callers:

```
                  +----------------------------------------------+
                  |                 Public / VPN                 |
                  +----------------------------------------------+
                            |                           |
                 port 8000  v                port 5173  v
                     [ Gateway ]                  [ Frontend ]
                  (FastAPI Gateway)            (React Control Panel)
                            |
           =================|======================================
           INTERNAL ISOLATED NETWORK (No external ports bound)
           =================|======================================
                   +--------+--------+--------+
                   |                 |        |
                   v                 v        v
              [ LocalAI ]       [ local-tts ] [ Streaming STT ]
             (port 8080)       (port 8880)    (port 8088)
```

1. **Host Port Binding:**
   - ONLY port `8000` (FastAPI Gateway) and port `5173` (Frontend) are accessible on the host/VPN network.
   - LocalAI, Kokoro TTS, and Streaming STT services bind only on the internal Docker bridge network `private_internal: true`.
2. **Access Control:**
   - Direct requests to LLM, STT, and TTS require API keys with explicit scopes (`llm`, `stt`, `tts`, `stt_stream`, `voice`).
   - Admin routes (`/v1/admin/*`, `/v1/models/installed`, etc.) require role `admin`.
   - Single-use browser tickets are consumed immediately upon WebSocket connection.

## 2. Monitoring & Metrics (Prometheus)

The gateway exports real-time metrics in standard Prometheus text format at `GET /metrics`.

### Configuration
- Scrape configuration: [`deploy/prometheus/prometheus.yml`](../../deploy/prometheus/prometheus.yml)
- Alerting rules: [`deploy/prometheus/alerts.yml`](../../deploy/prometheus/alerts.yml)

### Core Metrics Exported
| Metric Name | Type | Description |
|---|---|---|
| `voice_agent_requests_total{endpoint, status}` | Counter | Total count of HTTP/WS requests processed by endpoint and status code. |
| `voice_agent_active_streams{type}` | Gauge | Current count of active concurrent streaming connections (`voice` or `stt`). |
| `voice_agent_tokens_total{endpoint}` | Counter | Cumulative tokens processed by LLM backend. |
| `voice_agent_audio_seconds_total{endpoint}` | Counter | Cumulative audio duration processed across STT and TTS backends. |
| `voice_agent_turn_latency_seconds_bucket{le}` | Histogram | Voice turn latency distribution with buckets `[0.05, 0.1, 0.25, 0.5, 1.0, 2.5, 5.0, 10.0, +Inf]`. |

### Alerts Configured
1. **`High5xxErrorRate`**: Triggers when 5xx errors exceed 5% over 1 minute.
2. **`HighTurnLatency`**: Triggers when p95 voice turn latency exceeds 3.0 seconds over 2 minutes.
3. **`ActiveStreamSaturation`**: Triggers when active voice streams reach or exceed 8 concurrent sessions.

## 3. Database Backup & Disaster Recovery

### Online Atomic Snapshots (`VACUUM INTO`)
- SQLite database runs in **WAL mode** (`PRAGMA journal_mode = WAL; PRAGMA busy_timeout = 5000;`).
- Backups are performed via SQLite's atomic `VACUUM INTO` command, which:
  - Produces a consistent, fully compacted SQLite database file.
  - Does NOT lock out active writers or readers.
  - Can be triggered live without stopping the service.

### Backup Methods
1. **Automated Cron / CLI Script:**
   ```bash
   ./scripts/backup-db.sh
   ```
   - Automatically checks database integrity (`PRAGMA integrity_check`).
   - Retains the 20 most recent backups in `data/backups/`.
2. **Admin API Endpoint:**
   ```bash
   curl -X POST http://localhost:8000/v1/admin/backup \
     -H "Authorization: Bearer <ADMIN_KEY>"
   ```
   Returns:
   ```json
   {
     "status": "ok",
     "backup_file": "app-backup-20261115-151000-123.db",
     "backup_path": "/data/backups/app-backup-20261115-151000-123.db",
     "size_bytes": 1048576,
     "integrity": "ok",
     "created_at": 1794736200.0
   }
   ```
3. **Listing Backups:**
   ```bash
   curl http://localhost:8000/v1/admin/backups \
     -H "Authorization: Bearer <ADMIN_KEY>"
   ```

### Restore Procedure
```bash
./scripts/restore-db.sh data/backups/app-backup-20261115-151000-123.db voice_platform.db
```
The restore script:
1. Validates source backup integrity with `PRAGMA integrity_check`.
2. Creates a safety pre-restore backup of the target database (`voice_platform.db.pre-restore-<timestamp>`).
3. Replaces target file and removes stale `-wal` and `-shm` index files.
4. Verifies restored database integrity and reports record counts.

## 4. Operational Pre-Flight Checklist

Before opening external caller traffic:
- [x] Admin API key is set via `ADMIN_API_KEY` (no default development key accepted).
- [x] `API_KEY_HASH_SECRET` is set to a 32+ byte high-entropy secret.
- [x] CORS origin allowlist configured explicitly (wildcards with credentials rejected).
- [x] Database initialized in WAL mode with busy timeout.
- [x] Zero-transcript logging invariant verified (no customer prompts or transcripts in logs).
- [x] Quota enforcement verified (`max_daily_tokens`, `max_daily_audio_seconds` return 429 when exhausted).
- [x] Prometheus `/metrics` endpoint reachable and active stream gauges verified.
- [x] Backup script and restore verification tested successfully.
